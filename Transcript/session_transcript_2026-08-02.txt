Bug found (blocking, compile-time): SYSTOLIC_ARRAY.sv line 20

in intent - a PE's out_valid feeds in_valid_array[i][j+1], so the valid flag

6. FIFO.sv
================================================================================
Request: check newly added FIFO.sv (depth-8, single-lane).

Bug found: the d_out/mem-write always_ff block used `else if` between the
write branch and the read branch:
  if (wea && !ff_full) mem_fifo[wr_ptr[2:0]] <= d_in;
  else if (rea && !ff_empty) d_out <= mem_fifo[rd_ptr[2:0]];
This makes write and read mutually exclusive within a cycle, but wr_ptr and
rd_ptr (in separate always_ff blocks) advance independently of each other
with no such exclusivity. On a cycle with simultaneous wea+rea, rd_ptr still
advances but d_out is never loaded with the entry it just skipped past -
that FIFO entry is silently dropped.

Proven with a standalone probe (push A,B,C; read A; simultaneous push D +
read; read again): got A, then a stale value instead of B, then C directly -
B was lost.

Fix applied: made the write-to-mem and read-to-d_out independent (two `if`
statements instead of if/else-if), matching how the pointers already behave.
Reran the probe: correctly got A, B, C in order.

Rest of FIFO.sv (ff_empty/ff_full circular-pointer logic, pointer widths,
overflow/underflow guards) verified correct.

7. FIFO_All.sv (4-lane wrapper around FIFO.sv)
================================================================================
Request: check FIFO_All.sv.

Verified via two testbenches:
  - Data path: pushed 3 batches of 4-lane staggered data (matching real SA
    timing), including push/pop landing on the same cycle (the exact
    scenario the FIFO.sv bug above would have broken). All correct, all
    lanes synchronized, no data loss.
  - inject/counter/inject_ena: 8 injects with no pops correctly saturates

Note (not fixed, just flagged): ff_full from each lane FIFO is computed but
never used/exposed in FIFO_All - no backpressure/error signal if a lane ever
overflows. Fine as long as inject_ena is respected by the caller.

9. Top_Module.sv - data_out/result swap + FIFO_All output_valid timing bug
================================================================================
Request: check IO after switching which signal (data_out vs result) is the
module's external output port.

Confirmed: `result` is now the real external output, sourced from FIFO_All -
correctly fixes the earlier dangling-result issue. `data_out` became the
internal wire feeding FIFO_All.d_in from SA's raw output.

Bug found (significant, timing): FIFO_All's `output_valid` was purely
combinational (`assign output_valid = all_ready && pop;`) and doubled as the
`rea` signal driving all 4 lane FIFOs. Since each FIFO's d_out is a
registered read (1-cycle latency), output_valid ends up announcing "data
ready" exactly one cycle BEFORE d_out actually contains the freshly-popped
value.

Proven with a probe modeling a standard downstream consumer
(`always_ff @(posedge clk) if (output_valid) latch <= d_out;`): the consumer
latched a stale/reset value (0) instead of the freshly popped word.

User initially asked to just wrap the existing assign in an always_ff; this
was explained NOT to fully fix it, because output_valid also drives the
FIFOs' rea - registering it in place would delay the actual reads by the
same cycle, so the misalignment would persist, just shifted later. User
agreed to the two-signal split instead.

Fix applied to FIFO_All.sv:
  - Added combinational `pop_fire = all_ready && pop`, now driving `rea`
    into the 4 lane FIFOs (reads still happen exactly on the pop cycle,
    unchanged timing).
  - `output_valid` is now a registered, 1-cycle-delayed copy of `pop_fire`,
    aligning with the cycle d_out actually holds the popped data.
  - counter/inject_ena logic switched to key off `pop_fire` (undelayed)
    instead of the old output_valid, so credit accounting still happens on
    the correct cycle.

Reran the downstream-consumer probe: correctly latched the popped value.
Reran both FIFO_All regression tests (data path, counter) - both still pass.

10. Controller.sv - FSM rework to use FIFO_All (IDLE/LOAD_wgt/STREAM)
================================================================================
Request: check the FSM after it was changed to stream activations through
FIFO_All instead of the old single-shot ACT/WAIT/DONE flow.

Bug found (syntax): trailing comma in the parameter list -
  parameter IDLE = 3'b001, LOAD_wgt = 3'b010, STREAM = 3'b100,;
Confirmed via compile failure. Fixed (removed trailing comma).

Bug found (width/correctness): act_offset was still declared `[1:0]` (max 3)
but now compared against and incremented toward `num_act`, a runtime
10-bit count. For any num_act > 3, act_offset wraps at 2 bits and never
equals num_act - FSM gets stuck in STREAM forever, only ever re-reading 4
activation addresses. Fixed by widening act_offset to [9:0].

Verified via simulation (Controller -> SRAM -> SKEW_Unit chained directly,
bypassing Top_Module):
  - 6 distinct activation words (num_act=6, > the old 2-bit limit) arrive at
    the SKEW_Unit output in the correct order, no loss/duplication.
  - Same test repeated with a 4-cycle inject_ena stall injected mid-stream -
    still correct, no loss/duplication, stream resumes cleanly.

Note: an earlier probe that checked addr_act's value at the same cycle as
each start pulse showed addr_act "one cycle ahead" of the data index at that
moment - initially looked like a bug, but this is expected pipelining
(addr_act is the next prefetch address, one cycle ahead of the data start is
currently validating, same pattern as the original single-shot design). The
direct Controller->SRAM->SKEW_Unit data test confirmed no actual bug.

Flagged (not part of Controller.sv, cross-file gap at the time): Top_Module
had not yet been updated to connect the new num_act/inject_ena Controller
ports - would leave them floating if compiled as part of the full design.

User then independently tightened enb_act to also gate on
`inject_ena && (act_offset < num_act)` (previously enb_act was unconditional
across the whole STREAM state) - avoids wasted/extra SRAM reads past num_act
or during a stall. Re-verified the streaming datapath test still passes with
this change.
